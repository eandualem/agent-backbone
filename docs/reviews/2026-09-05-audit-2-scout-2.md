## New candidates

- **S2-A — wrong PTY target:** `terminal/_pty.py:75` passes a raw session
  target. Join app, release dimensions, stop app leaving app-2, then resize:
  Socket.IO reattaches without another existence check and tmux can prefix
  match app-2. Use the shared exact target. Source validated; unassigned.
- **S2-B — unreachable early Claude action detector:** `runtimes/claude.py`
  restricts PreToolUse to ExitPlanMode/AskUserQuestion, while
  `hooks/claude_hook.py` relies on its shell branch to log outgoing PR intent
  before the webhook arrives. Align wiring with intended detector semantics.
- **S2-C — unconsumed delivery reported submitted:** `runtimes/base.py:667`
  uses the human-input detector, which excludes envelopes at line 558.
  Mock pane `❯ [via:backbone from:sender] review this` returns `submitted`
  even though the message remains in the prompt. Separate buffered delivery
  detection from human typing. Reproduced with mocked capture.
- **S2-D — startup ignores fresh busy hook:** `agents/launch.py:298` falls
  through from a fresh busy record to terminal idle detection. A busy snapshot
  timestamp 100, launch time 90 and pane `❯` returns ready. Reproduced with
  mocked state/capture. Retain hook authority while waiting for startup.
- **S2-E — hook settings truncate during launch:** `hooks/install.py:132`
  writes shared settings with `write_text`; another agent's launch can read
  an empty/partial Claude or Gemini settings file. Atomic replacement is
  needed for settings as well as the already-fixed hook scripts.
- **S2-F — overlapping PTY creation leaks a process:** `_pty.py:284` pops
  an old session before awaiting cleanup. A second create starts/stores a
  new PTY; the first resumes and overwrites it without cleaning it. Reproduced
  with fake PTYs and an Event barrier: two new instances, one unreachable
  and not cleaned. Serialize the per-viewer/session lifecycle.
- **S2-G — OpenCode state omits runtime identity:** `hooks/opencode_hook.js`
  record omits `runtime`. After changing runtimes, launch's legacy handling
  accepts its session ID as belonging to the new runtime and passes a foreign
  resume ID to Claude/Codex. Stamp OpenCode's runtime in its records.

## Validated earlier recommendations

1. **PTY orphan identity:** `_pty.py` signals saved bare PIDs after restart;
   reuse can kill unrelated processes. Coordinator assigned implementation
   in `_pty.py`, its tests and docs/api.md. Persist/check birth and full attach
   command, skip legacy/malformed/unverifiable records. Tests mock all signals.
2. **Queue retention:** delivered/expired full message rows never pruned.
   Assigned to another scout; no database edits here.
3. **Serialized agent lifecycle:** store updates read old snapshots and upsert
   all fields across awaits, losing concurrent independent changes. Resolve
   and register happen before the start lock; forget can remove a resolved
   agent before start. Needs orchestration and store mutation serialization.
4. **Shared AgentSpec validation:** direct store updates can persist unsupported
   runtimes and accept malformed fields that API validation rejects.
5. **Command-aware acknowledgement:** echo of a quoted gh comment yields an
   acknowledgement (reproduced). Before-tool logging is intent, not successful
   execution; separate own-event attribution from acknowledgement evidence.
6. **Single runtime metadata source:** config IDs, registry/detection order and
   HOOK_FILES require separate edits. `install_hook_script` is an unreferenced
   Claude-specific compatibility helper outside runtime ownership.

The prior fixed findings were not re-reported. Codex's intentional queued
delivery interruption remains the previous owner decision, not a new defect.

## Durable polling cursor assignment

Added poll_cursors(repo primary key, since) and EventRepo accessors; regenerated
the single initial migration as 77253d1cd6b0. The poller persists a configured
lookback boundary before its first fetch, independent of event receipt times.
A batch advances only after all hydration and dispatch succeed, to the later of
poll-start time and newest source timestamp, minus two minutes of overlap,
never backward. Poll-start is captured before either GitHub listing. Database save
precedes the memory update; read/save/fetch/conversion failures isolate the
repository and keep its old boundary. Invalid, timezone-less or future cursors
are logged and reset to configured lookback before fetching.

Thirty-eight focused tests pass: partial first batch hydration/dispatch failure
and new-poller restart, successful cursor restart and same-second late item,
initial/read/advance persistence failures with another repository continuing,
malformed cursor fallback, per-repo storage, independent event retention,
persistent DB reopen and old SQLite schema restamp preserving event data.
