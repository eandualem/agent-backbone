## Recommendations, ranked

1. **R1 — durable per-recipient GitHub delivery receipts/outbox (data loss).**
   At `_router._deliver` and `_ingest._store_route_mark`, persist fan-out targets
   and completion/storage receipts before marking an event handled. Retry only
   unresolved recipients. Needed for S1-5 and partial fan-out crash recovery;
   requires schema and delivery/ingestion transaction design, beyond a safe
   outcome-only patch. The durable poll cursor does not solve this.
2. **R2 — serialize complete agent lifecycle and store mutations (lost updates).**
   `services/agents/store.py:193` reads a snapshot then upserts all fields across
   awaits; two independent updates overwrite each other. `operations.py:93,105`
   permits forget between resolution and start. Move per-agent serialization
   around resolve/register/start/forget and use atomic field updates/versioned
   writes. PTY viewer locks and the delivery lock do not fix this separate race.
3. **R3 — command-aware intent and acknowledgement (premature completion).**
   Hook regexes accept quoted examples of gh issue comment and log before-tool
   intent as acknowledgement. Parse actual executable commands, record intent
   separately for own-event suppression, and acknowledge successful execution.
   Include S2-B wiring only after that distinction is established; widening
   Claude's matcher alone would increase false acknowledgements.
4. **R4 — shared AgentSpec validation (inconsistent entry points).**
   `services/agents/store.py:193` accepts runtime/field updates that the API
   rejects. Centralize model, runtime and repository validation in the shared
   domain/store entry point, then have API/CLI use it; define compatibility for
   already-stored records. API state/sender bounds in this PR are narrower.
5. **R5 — actual age and dependent priority inputs (ordering).**
   `services/routing/_priority.py` uses issue number as age, which is not
   comparable across repositories; `_targets.py` never supplies dependent count.
   Carry source creation time and dependency counts into scoring, then test
   cross-repo ordering. Docs now state the existing proxy/unused-input contract.
6. **R6 — shared queue snapshots and bounded status fan-out (I/O).**
   Dependency sync, pending selection, offline counts and lifecycle selection
   independently fetch overlapping GitHub queues; status also reads sequentially.
   Introduce a scoped per-tick repository snapshot with explicit freshness and
   bounded concurrency. Keep final readiness checks immediate. Complete queue
   pagination fixes correctness but makes sharing those requests more valuable.
7. **R7 — config-driven job/integration lifecycle (operational consistency).**
   `api/app.py:_register_jobs` captures intervals/intake at boot while config
   updates publish immediately. Reconcile job creation/removal/periods and
   integration enablement on publish, with safe cancellation/start semantics.
   Until then the docs explicitly require restart for these consumers.
8. **R8 — one runtime metadata registration source (extension maintenance).**
   Config IDs, registry/detection order and hooks.install.HOOK_FILES still need
   coordinated edits. Consolidate declarative metadata without breaking leaf
   imports or standalone hook scripts. Removed dead helpers do not complete
   this larger change.
9. **R9 — one integration registration source (extension maintenance).**
   `services/integrations/_registry.py:19` and `_notify.py:32` separately register
   lifecycle and static notifier support. Use one descriptor supporting both
   server-owned instances and CLI static notification without import cycles.
10. **R10 — amortized RecentKeys expiry (performance).** Use ordered expiry or
    a periodic bounded sweep in `recent.py:29`; preserve variable TTL and
    duplicate semantics. Benchmark representative bursts before choosing the
    data structure; no unsupported throughput claim is made here.

## Deliberately retained behavior and limits

- Codex's queued-delivery interruption is the prior owner's explicit decision;
  it was not reopened as a new busy-interruption finding.
- Public issue listing stays bounded by default. Internal work queues request
  complete pagination before filtering and scoring.
- Envelopes remain provenance conventions, not authenticated sender identities;
  existing summary/link and bounded comment-preview contracts are retained.
- Terminal-only idle has no reliable transition timestamp; grace uses hook
  transitions. Locks are in-process, not cross-server distributed locks.
- Cursor storage starts from configured lookback for repositories without a
  durable cursor, including first upgrade. Two-minute overlap is finite; this
  does not promise recovery of arbitrarily late upstream updates or delivery
  exactly once across partial fan-out crashes. Webhook backfill runs once per
  startup; failed batches remain eligible on the next run/restart.
- Queue rows with unknown completion time and unverifiable legacy PTY identities
  are deliberately retained/skipped rather than guessed. No live kill tests,
  new dependencies, new issues, or pushes to main/develop were used.
- The existing mocked PTY-reader unawaited-coroutine warning predates this run.
